## 1. Mục tiêu

1. Cài đặt **V1 Standard** đúng canonical C1–C6 → **qua TC1–TC8** (golden `docs/root/Nhom01_VDChayTay.md` Phần 11).
2. **Level 1 threading** thật (không đơn luồng ẩn): Reconstruction song song theo node, Mining song song theo cây con gốc; Construction đơn luồng (giữ INV-B).
3. **Áp dụng GoF** ở điểm hợp lý; tạo ranh giới module hoá cho V2 (điểm sửa đổi) và debug app G4.
4. Logging/benchmark **độc lập thuật toán** (Decorator ở contract, `dhopm-common`) — tắt log = zero-overhead.
5. Deterministic (INV-E): cùng input/tham số → **bit-for-bit** cùng kết quả với mọi pool size.
6. Ghi lại **actual double** của TC1–TC8 làm **golden double** cho V2 so sánh.
7. Benchmark sơ bộ (mushroom ∂=6%, retail ∂=0.1%; chia 5 phần) + **bộ tài liệu project V1** đầy đủ.

## 2. Phạm vi

**Trong:** Global DHO-List + Reconstruction + DUBO + Conditional list + Mine (DFS) theo canonical; input text/FIMI (tái dùng `dhopm-common`); Level 1 threading; instrumentation decorator dùng chung; CLI benchmark sơ bộ; tài liệu V1.

**Ngoài (để V2/V3):** tối ưu cấu trúc dữ liệu (ID+name, primitive, List/Set thay Map), Construction song song, work-stealing, work-stealing chia cây sâu, mọi mẹo làm giảm độ rõ ràng.

## 3. Quyết định giai đoạn

| # | Quyết định | Giá trị |
|---|---|---|
| G1-D1 | Item biểu diễn | `String` name|
| G1-D2 | DHO-List | `LinkedHashMap<Item, Node>` (thứ tự tạo + tra cứu) + `ArrayList<Node>` để sort |

| G1-D6 | Golden double | Snapshot actual double TC1–TC8 dạng JSON trong module V1 làm mốc V2 |

## 4. Kiến trúc & ánh xạ GoF

```
dhopm-common (có sẵn)
└── contract: Engine, Pattern, MineResult  (+ G1: TimedEngine decorator, RunMetrics)
└── config/io/testkit/util: tái dùng (MiningConfig, readers, GoldenRunner, WorkerPool, Log)

dhopm-v1-standard (MỚI)
package dhopm.v1
├── model    : Item? (dùng String), Entry(tid,len), DHONode(item, entries, doValue), DHOList
├── construction : DHOListBuilder (scan batch, INV-B), StreamStatus
├── metrics  : MetricCalculator (F1–F6: occupancy, decay, DO)
├── reconstruction : Reconstructor (reset DO, cộng dồn tuần tự, stable sort) + Level 1 tasks
├── dubo     : DuboCalculator (C1 theo canonical 2.3; nhóm entry theo |T| bằng TreeMap)
├── mining   : ConditionalListBuilder (two-pointer, INV-D), Miner (DFS C2/C3/C4)
├── engine   : MiningEngine implements Engine (loadBatch/mineNow) — Facade
└── cli      : Main (args: dataset, ∂, f, workers; nạp reader; in DOP + metrics)
```

| Pattern (GoF) | Đặt vào | Mục đích (từ plan 01 mục 4.1) |
|---|---|---|
| **Strategy** | Metrics / DUBO | Cô lập công thức, test biến thể, giao cho V2 đổi chiến lược |
| **Factory Method / Builder** | Dựng `DHONode`, `DHOList` | Kiểm soát tạo dựng, dễ thêm lựa chọn cấu trúc |
| **Template Method** | Pipeline 3 giai đoạn (load → reconstruct → mine) | Khung cố định, bước con cho subclass V-sau |
| **Facade** | `MiningEngine` | API gọn cho CLI/benchmark/app |
| **Decorator** | `TimedEngine` (contract chung) | Đo/ghi **ngoài hot path**; tắt = zero-overhead |
| **Observer** | Progress callback (tuỳ chọn, qua `ProgressListener` interface) | G4 loading screen không trói vào engine |

Ranh giới quy ước bắt buộc (canonical): entry append theo TID tăng (INV-B); DO/DUBO của node tính **tuần tự** (C5); conditional list **không** sort lại (INV-D); so sánh `≥ minSup − ε`, ε=1e-9 (C4); tie-break stable theo thứ tự tạo node (C3).

## 5. Công việc & Milestone

**M1 – Setup hạ tầng**
- [ ] Thêm module `dhopm-v1-standard` + `dhopm-bench` vào `implementation/pom.xml` (modules), dependency `dhopm-common`.
- [ ] `TimedEngine` (Decorator) + `RunMetrics` (`loadMs, mineMs, patterns, lastTid, minSup, heapMB`) vào `dhopm-common` (dùng `Log` ghi khi bật).
- [ ] CLI `dhopm.v1.cli.Main`: nạp FIMI/text (reader chung), chạy engine, in DOP + metrics.

**M2 – Mô hình dữ liệu & Construction (GĐ1)**
- [ ] `Entry(tid, len)`, `DHONode` (item, `ArrayList<Entry>`, `doValue`, `support() = entries.size()`).
- [ ] `DHOList` (createOrGetNode, append, `stableSortBySupport()`).
- [ ] `DHOListBuilder`: scan batch đơn luồng theo TID tăng; fail-fast nếu TID giảm (INV-A).
- [ ] `StreamStatus`: tổng transaction, TL; `minSup = partial × tổng`.

**M3 – Reconstruction & Metrics (GĐ2)**
- [ ] `MetricCalculator`: `occupancy = len/|T|`, `decay = f^(TL−tid)`, `DO(node)` tích luỹ tuần tự.
- [ ] `Reconstructor` + Level 1: 1 task/node (invokeAll, chờ hết → stable sort); kháng lỗi qua `Future.get`.
- [ ] Unit test: `DO(A)=0.8551`, `DO(F)=1.2553` tại TL=8, f=0.9 (đối chiếu chạy tay).

**M4 – Mining (GĐ3)**
- [ ] `DuboCalculator` theo C1 (nhóm entry theo |T| tăng dần; `DUBO = max_k ...`).
- [ ] Unit test DUBO: `E=4.5, B=1.8, CD=1.6402, AF=0.93, CDE=1.181, F=3.0375` (TL=8, f=0.9).
- [ ] `ConditionalListBuilder`: two-pointer trên entry sắp TID; không sort kết quả (INV-D).
- [ ] `Miner` DFS: skip khi `support < minSup` (C2); add DOP khi `DO ≥ minSup−ε` (C4); prune khi `DUBO < minSup`; gộp kết quả sau join.
- [ ] Level 1 Mining: 1 task/cây con gốc (node đủ điều kiện mở rộng); DFS tuần tự trong task.

**M5 – Nghiệm thu đúng đắn**
- [ ] `GoldenRunner` chạy **TC1–TC8** → pass (tolerance 1e-6); chụp **actual double** → `golden-doubles-v1.json` (G1-D6).
- [ ] Determinism: chạy lại pool size 1/2/4/cpu → so **bit-for-bit** (INV-E, C5).
- [ ] Thread-safety: chạy `-ea`, nhiều lần; không race (gộp sau join).
- [ ] Log/benchmark độc lập: bật/tắt `Log` không đổi kết quả; đo `TimedEngine` không nằm trong hot path.

**M6 – Benchmark sơ bộ & bộ tài liệu V1**
- [ ] `dhopm-bench`: driver incremental — chia dataset 5 phần, chạy engine mỗi phần, đo 3 giai đoạn + peak heap (`Runtime`), xuất CSV/text.
- [ ] Chạy 2 dataset đại diện: `mushroom.dat` (∂=6%, dense) + `retail.dat` (∂=0.1%, sparse); f=0.9; ≥3 lần lấy median.
- [ ] **Bộ tài liệu project `dhopm-v1-standard`** (đặt trong module):
  - [ ] `README.md` (chạy/tham số/CLI).
  - [ ] `docs/design.md` (cấu trúc & từng thành phần/hàm — ghi trong lúc làm; chèn bảng GoF G1-D5).
  - [ ] `docs/test-report.md` (test plan + kết quả TC1–TC8).
  - [ ] `docs/benchmark.md` (số liệu sơ bộ 2 dataset).
- [ ] Đóng dấu: V1 = **golden reference** cho V2/V3.

## 6. Nghiệm thu (Done criteria — G1)

- [ ] TC1–TC8 pass trên `dhopm-v1-standard`.
- [ ] Determinism bit-for-bit với pool size 1/2/4/cpu (INV-E, C5).
- [ ] Level 1 threading thực sự dùng (số task Reconstruction = số node; số task Mining = số cây con khả thi) — xác nhận qua test/log.
- [ ] Canonical: skip/prune đúng C2; stable sort C3; ε C4; conditional không sort INV-D.
- [ ] `TimedEngine` ở `dhopm-common` — tắt log không thêm chi phí đáng kể.
- [ ] Benchmark sơ bộ có số liệu (mushroom + retail, 5 phần, 3 giai đoạn, median).
- [ ] Bộ tài liệu project V1 đầy đủ (M6) + `golden-doubles-v1.json` lưu được.
- [ ] `mvn test` (via `run.bat`) xanh.

## 7. Rủi ro

| Rủi ro | Xử lý |
|---|---|
| Lệch chữ số thập phân so với bảng 4 chữ số | Tolerance 1e-6 với golden; đối chiếu công thức C1–C4 + chạy tay [2] |
| Race khi gộp kết quả Mining | Gộp **sau join** (G1-D4); sau đó mới cân nhắc concurrent set |
| Hiểu sai C2 (skip khi sup<minSup) | Đối chiếu pseudocode Mine (line 03 [1]) và hành vi G trong chạy tay |
| DFS đệ quy sâu → stack overflow dataset lớn | V1 ghi nhận giới hạn; benchmark dataset nhỏ trước; V2 giải quyết |
| Instrument làm chậm | Nằm ở Decorator contract; đo trong M5 xác nhận zero-overhead khi tắt |
