## 1. Mục tiêu

1. **Đo được giá trị của ε**: biến "đọc toàn bộ lịch sử stream" thành "duy trì cửa sổ trượt hữu hạn" — bộ nhớ và thời gian gần như **độc lập độ dài stream**.
2. **Giữ đúng bất biến bảo toàn**: `ε = 0 ⇒ V2 ≡ V1 ≡ paper` **bit-for-bit** (INV-I); ` DO_win − DO_full  ≤ ε` (INV-G).
3. **Giải quyết "tìm rỗng mất 87–300 s"**: short-circuit theo trần DO + bound `min(DUBO, Z(X))` ⇒ trả về ∅ **tức thì** kèm thông điệp có số liệu.
4. **Đưa ngưỡng `∂` về miền có nghĩa**: validator + lệnh `window` cho biết `∂` tối đa khả thi với `(f, ε)` đã chọn.
5. **Bộ tài liệu V2** + báo cáo ablation V1 ↔ V2.

### 1.1 Vì sao G2 quan trọng (bằng chứng từ G1)

  Số liệu đã đo   Nguồn   Ý nghĩa  
 --- --- --- 
  `retail.dat` (88 162 tx) phần 5 = **86 949 ms → 0 pattern**   `dhopm-v1-standard/docs/benchmark.md`   Chạy gần 1.5 phút để kết luận "rỗng" — biết trước bằng 1 phép tính  
  `mushroom.dat` (8 124 tx) phần 5 = **300 751 ms → 0 pattern**   như trên   5 phút cho kết quả rỗng  
  DO bị chặn trên **≈10** ở `f=0.9`   `benchmark.md`   `minSup = ∂×N` với `∂` của paper vượt trần nhiều lần  

> Nguyên nhân gốc: ` X  ≤  T_t ` ⇒ `DO(X) ≤ Σ f^k = Z(f,TL)`. Không có ai dùng điều này trong paper.

## 2. Phạm vi

**Trong phạmvi:**
- `dhopm-common`: `WindowMath`, `WindowInfo`, `ParameterValidator`, `WindowAwareEngine`/`WindowListener`; đổi tên `epsilon` → `epsilonCmp`; thêm `epsilon` (cửa sổ).
- `dhopm-v2-epsilon`: GĐ0 evict O(1) (handle 2 tầng), `minSup` 2 pha, `Z`/`Z(X)`, `UB'(X)`, short-circuit, Level 1 threading.
- TestKit: TC9–TC18 + bảng biên E1–E10.
- CLI: `window`, `validate`, `sweep`; `windowInfo` trong output.
- Báo cáo đo ε + ablation V1 ↔ V2.

**Ngoài phạm vi (để dành G3/G4):**
- Bỏ lớp Handle / dùng `int txSlot` + bảng trạng thái → V3.
- SoA/primitive array, precomputed decay lookup → V3.
- `ForkJoinPool`, chia cây sâu, Construction song song → V3.
- Data-oriented thuần, Level 3, memory-mapped I/O → V4.

  #   Quyết định   Giá trị   Căn cứ  
 --- --- --- --- 
  G2-D1   Công thức cửa sổ   `W = ⌈ln(ε(1−f))/ln f⌉`; `ε=0` hoặc `f=1` ⇒ `W=∞`; `ε ≥ 1/(1−f)` ⇒ **lỗi**   D10  
  G2-D2   Đơn vị ngưỡng   `minSup = ∂ × min(TL, W)` (2 pha)   D11  
  G2-D3   Cơ chế evict   Handle 2 tầng `ref1 → ref2`; evict = `ref2.tx = null`; compaction bằng `head`   D12  
  G2-D4   Vị trí evict   Trong `loadBatch`, **đơn luồng**, **trước** mọi pha song song   INV-E  
  G2-D5   Transaction ngoài cửa sổ ngay từ đầu   **Không ghi entry** (rẻ hơn evict)   `plans/02` §5.1  
  G2-D6   Trần & short-circuit   `minSup > Z(f,TL)+ε_cmp` ⇒ ∅ O(1) + cảnh báo   D19  
  G2-D7   Bound prune   `UB'(X) = min(DUBO(X), Z(X))`; `Z(X)` tính cùng vòng duyệt entry   D19  
  G2-D8   C2 với cửa sổ   Dùng **support sống**; vẫn hợp lệ vì `DO(X) ≤ Z(X) ≤ support_sống(X)`   `plans/02` §5.4  
  G2-D9   DUBO sau evict   Tính **chỉ trên entry sống** ⇒ Lemma 2 vẫn đúng   `plans/02` §5.5  
  G2-D10   Threading   Giữ **Level 1** như V1 (V2 tập trung ngữ nghĩa, chưa tối ưu)   `plans/00` §3  
  G2-D11   Vị trí code dùng chung   `WindowMath` + validator ở **`dhopm-common`** (V1 dùng để in cảnh báo, không đổi hành vi)   D22  
  G2-D12   Tên tham số   `epsilon` = cửa sổ (mặc định `1e-6` ở V2+); `epsilonCmp` = sai số so sánh (`1e-9`)   D9  
  G2-D13   Entry giữ 3 trường   `record Entry(Handle ref1, int ref2, long tid)`; coi là **sống** chỉ khi `ref1 != null && ref1.tx != null && ref1.tid == entry.tid` — **bắt buộc** chống lỗi âm thầm do slot vòng tròn bị tái dùng (D39)   `plans/02` §5.2.1  
  G2-D14   Hai công thức `maxPartial`   Validator dùng **chính xác** `Z(f,TL)/N_eff`; lệnh `window` (chưa có `TL`) chỉ trả **xấp xỉ** `1/((1−f)·W)` với hậu tố `…Asymptotic`, `…Exact = null`   D38  
  G2-D15   `windowOverride`   Chỉ nghiên cứu; khác `W(f,ε)` ⇒ cảnh báo + ghi `research-mode` vào output; vượt lớn hơn thì vô hại   D40

## 4. Kiến trúc

```
dhopm-common (MỞ RỘNG)
└── config     : MiningConfig  + epsilon, windowOverride, maxWindow   (đổi epsilon→epsilonCmp)
└── window (MỚI)
    ├── WindowMath        computeWindow(f,ε) · maxDO(f,TL) · maxPartial(f,ε)
    ├── WindowInfo (MỚI)  record(windowSize, effectiveTransactions, minSup, maxDO,
    │                            evictions, liveEntries, deadEntries)
    └── ParameterValidator (MỚI)  kiểm tra miền + cảnh báo (mã lỗi ổn định)
└── contract  (MỚI)
    └── WindowAwareEngine + WindowListener   (báo evict/live/dead)

dhopm-v2-epsilon (MỚI)   package dhopm.v2
├── window   : Handle(tid,len,tx) · WindowBuffer (circular W slot, evict O(1))
├── dho      : Entry(ref1,ref2) · DHONode(head,size,entries) · DHOList
│              └─ support() = size − head   (O(1))
├── construction : DHOListBuilder  (GĐ1: bỏ qua tx ngoài cửa sổ)
├── window   : WindowManager      (GĐ0: evict trong loadBatch)
├── metrics  : MetricCalculator · ZCalculator (Z(f,TL), Z(X))
├── reconstruction : Reconstructor (dời head, DO chỉ trên entry sống) + Level 1 tasks
├── mining   : DUBOCalculator (DUBO + Z(X) → UB'(X)) · ConditionalListBuilder (C2, INV-D)
│              Miner (DFS, prune UB', support sống)
└── MiningEngineV2  pipeline GĐ0→GĐ3 + short-circuit
```

## 5. Công việc & Milestone

### M1 – Nền tảng cửa sổ trong `dhopm-common`
- [ ] `WindowMath.computeWindow(f, ε)` + `maxPartialExact(f, ε, TL)` + `maxPartialAsymptotic(f, ε)` (D38 — **hai hàm riêng, không được lẫn**).
- [ ] `WindowInfo` record.
- [ ] `ParameterValidator`: miền `∂ ∈ [0,1]`, `f ∈ (0,1]`, `ε ≥ 0`, `ε_cmp > 0`; lỗi cho `ε ≥ 1/(1−f)` (D30), cảnh báo cho `∂ = 0` (D31) và `∂ > maxPartialExact`.
- [ ] **`MiningConfig`**: đổi `epsilon` → `epsilonCmp`; thêm `epsilon` (mặc định `1e-6` ở thư viện; **giao thức Manager bắt buộc khai báo** — D41).
- [ ] `WindowAwareEngine` + `WindowListener` vào contract.
- [ ] **`WindowMathTest`**: đối chiếu bảng tra cứu `W` (`plans/00` §2.3.1), bảng `∂` khả thi (§6.4), và **bảng D38** (xấp xỉ vs chính xác) — bắt buộc có case `TL < W` để chống nhầm 2 công thức.
- [ ] **Đảm bảo V1 vẫn xanh** sau khi đổi tên tham số (TC1–TC8).

### M2 – Handle & Evict (GĐ0)
- [ ] `Handle` + `WindowBuffer` (circular, W slot, index `tid mod W`), `evict(tid)` O(1).
- [ ] **`Entry(Handle ref1, int ref2, long tid)`** — 3 trường, `tid` **bắt buộc** (G2-D13).
- [ ] `isLive(Entry)` kiểm `ref1 != null && ref1.tx != null && ref1.tid == entry.tid`; dùng ở **mọi** nơi đọc entry.
- [ ] `DHONode` có `head`/`size`; `support() = size − head`.
- [ ] GĐ0 trong `loadBatch`: bỏ qua ghi entry ngoài cửa sổ (G2-D5); evict khi `m − W ≥ 1` (G2-D4).
- [ ] **Test bắt buộc:** nạp `≥ 2W` transaction rồi kiểm **không** node nào đọc ra transaction đã bị tái sử dụng slot (lỗi âm thầm D39).

### M3 – `minSup` 2 pha & Reconstruction
- [ ] `minSup = ∂ × min(TL, W)`, tính tại `mineNow` (INV-F); ghi vào `WindowInfo`.
- [ ] `Reconstructor`: dời `head`, tính DO **chỉ trên entry sống**; threading Level 1 (mỗi node 1 task).

### M4 – Trần, bound & Mining
- [ ] `ZCalculator`: `Z(f,TL)` + `Z(X)`.
- [ ] `DUBOCalculator` trả `UB'(X) = min(DUBO(X), Z(X))` trong cùng vòng duyệt entry.
- [ ] **Short-circuit toàn cục**: `minSup > Z(f,TL)+ε_cmp` ⇒ trả ∅ O(1) + cảnh báo có số liệu.
- [ ] `Miner` DFS: C2 dùng support sống (G2-D8); prune bằng `UB'`.

### M5 – Nghiệm thu đúng đắn
- [ ] **TC1–TC8 với `ε = 0` trên V2 ⇒ bit-for-bit ≡ V1** (INV-I) — test bắt buộc, chạy trước mọi test khác.
- [ ] **TC9–TC18** xanh (định nghĩa ở `../plans/02` §6).
- [ ] **E1–E10** (bảng biên `../plans/00` §6.4) xanh.
- [ ] `DeterminismAssert` qua pool size {1,2,4,cpu}.
- [ ] Test `ε = 0` **không** kích hoạt cửa sổ (không evict, `W = ∞`).

### M6 – CLI & quan sát
- [ ] Lệnh `window`: in bảng tra cứu `W(f,ε)`, `N_eff`, `minSup`, trần `Z(f,TL)`, `∂` tối đa — **không cần dataset**. Vì không biết `TL` ⇒ chỉ trả `maxPartialAsymptotic` với hậu tố `…Asymptotic`, `…Exact = null` (G2-D14).
- [ ] Lệnh `validate`: lỗi/cảnh báo với **mã ổn định** (`INFEASIBLE_PARTIAL`, `EPSILON_TOO_LARGE`, `WINDOW_TOO_LARGE`, `PARTIAL_ZERO`).
- [ ] Lệnh `sweep`: quét nhiều tổ hợp `(ε, ∂, f)` → bảng (số DOP, runtime, memory, độ dài TB).
- [ ] `windowInfo` trong output của `mine`/`detail`; `golden` chạy TC1–TC18.

### M7 – Đo lường & báo cáo
- [ ] Instrumentation (đặt sau `if (enabled)`, **không** trong hot path): số lần evict, entry sống/chết, nodes explored, prune-hit ratio.
- [ ] **Đo độ lệch**: `max_X  DO_win(X) − DO_full(X) ` trên toàn bộ dataset benchmark ⇒ kiểm chứng INV-G ngoài test nhỏ.
- [ ] **Ablation V1 ↔ V2** trên ≥4 dataset (dense + sparse), cùng `(∂, f, ε, dataset)`, chia 5 phần, median ≥3 lần.
- [ ] **Scalability**: `kosarak` 200K→990K — chứng minh **memory đỉnh gần như phẳng** (NFR-4 của plan 02).
- [ ] Báo cáo ghi rõ phần cứng, JDK, số worker.
- [ ] Bộ tài liệu `dhopm-v2-epsilon`: README, design từng thành phần/hàm (kèm **lý do** handle 2 tầng), test report (TC1–TC18 + E1–E10), benchmark report.
