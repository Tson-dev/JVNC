## 1. Mục tiêu

1. **Cải thiện hiệu năng thực sự** so với V2 trên 10 dataset FIMI (mushroom, retail, kosarak, chess, connect, accidents, chainstore, pumsb, pumsb_star, newMushroom).
2. **Level 2 threading**: ForkJoinPool + work stealing; construction song song (có switch); reconstruction theo node; mining chia cây con đệ quy.
3. **Giữ kết quả trùng V2** (double đầy đủ): minOcc=0 ⇒ ≡ V1/V2; minOcc>0 ⇒ ≡ V2 (TC1–TC18 + E1–E10).
4. **Tận dụng cửa sổ minOcc**: mọi mảng giới hạn theo W (không theo N) ⇒ memory phẳng, cache-friendly.
5. **Báo cáo benchmark đầy đủ**: ablation V1→V2→V3, scalability 200K→990K (kosarak), chainstore 1.1M, median ≥3.

---

## 2. Phạm vi

- Toàn bộ thuật toán như V2 nhưng dựng lại **cấu trúc dữ liệu nội bộ** (SoA, primitive array, int itemId, không Handle).
- Giữ OOP nhẹ (class tối giản), **chưa** Data Oriented full (dành V4).
- NFR đầy đủ + benchmark + báo cáo.
- Không thêm tham số ngữ nghĩa mới (minOcc, ∂, f, workers đã đủ).

## 3. Tối ưu cấu trúc dữ liệu (trọng tâm V3, plan §4)

| # | Tối ưu | V2 (MinOcc) | V3 (Optimized) | Rationale |
|---|--------|-------------|----------------|-----------|
| 1 | Item | `String` | **`int itemId`** + dict `String↔int` | So/hash int trong vòng nóng; name chỉ IO |
| 2 | Global list | `LinkedHashMap<Item,Node>` | **`Node[]` index by itemId** (growable) | O(1) tra cứu, không boxing key |
| 3 | **Handle/evict** | `Entry.ref1 → Handle` (obj, 2 con trỏ) | **`int txSlot`** (index vào circular buffer) + `byte[] alive` | Bỏ class Handle; evict = `alive[slot]=0` O(1); INV H tự thoả |
| 4 | **WindowBuffer** | `Handle[]` | **SoA: `int[] txId; short[] txLen; long[] alive; double[] decay`** | Contiguous, cache-friendly, size = W |
| 5 | Entry/node | `Entry` record | **SoA per node: `int[] txSlot; int[] ref2`** | Giảm overhead object; locality |
| 6 | Support | `size−head` | `txSlot.length−head` (O(1)) | Không đếm lại |
| 7 | Sort support | `List.sort(Comparator)` | **Primitive sort `int[]`** theo support, stable theo creation order | Tránh boxing |
| 8 | DUBO length | `TreeMap<Integer,…>` | **Bucket array by length** | Không alloc mỗi node |
| 9 | Decay | `Math.pow` mỗi lần | **Lookup table `decayLookup[k] = f^k` cho `k=0..W−1`** | Chỉ W phần tử, không phụ thuộc TL |
| 10 | Conditional list | Tạo object mới | **Reuse buffer/arena**; node = bản ghi gọn | Giảm GC; giữ INV D |

> **Quy tắc:** Mọi thay đổi **không đổi thứ tự tính toán 1 node (C5)** và **không đổi tập DOP (INV E)**.

## 4. Threading Level 2 (bắt buộc, plan §5)

| Giai đoạn | Chiến lược |
|---|---|
| GĐ0 Evict | **Đơn luồng** trong `loadBatch` (C10, INV E) |
| GĐ1 Construction | **Optional song song**: chia batch K đoạn (K≈workers), mỗi worker dựng partial node (`txSlot[]` theo itemId), merge theo itemId ghép dải TID theo thứ tự (INV B). Có switch bật/tắt. |
| GĐ2 Reconstruction | **ForkJoinPool**: 1 task/node (giữ C5); pre-compute `decayLookup` trước dispatch. |
| GĐ3 Mining | **ForkJoinPool**: 1 task/cây con gốc; nếu ước lượng conditional nodes > ngưỡng ⇒ chia sâu hơn (task con cho cây con node j). Join kết quả theo thứ tự canonical (C6) ⇒ INV E. Ngưỡng min subtree chống overhead. |

## 5. Công việc & Milestone

### M1 – Baseline V2 (tuần 1)
- [ ] Chạy V2 benchmark trên 10 dataset (`dataset/`), f=0.9, minOcc cố định, ∂ trong miền khả thi (bảng 6.4 plan 00), 5 phần incremental.
- [ ] Ghi runtime 3 pha, peak memory, throughput, latency batch, **median ≥3**.

### M2 – Cấu trúc dữ liệu (tuần 2–3)
- [ ] Dictionary `String↔int` (IO layer tách biệt).
- [ ] Node SoA (`int[] txSlot`, `int[] ref2`), global index by itemId.
- [ ] **Bỏ Handle**: `txSlot` + `byte[] alive` trong WindowBuffer SoA.
- [ ] WindowBuffer SoA (`int[] txId; short[] txLen; double[] decay`).
- [ ] Decay lookup table `k=0..W−1`; fallback W=∞.
- [ ] Primitive sort support; DUBO bucket array.
- [ ] Microbenchmark từng thay đổi → ghi report; chỉ giữ phương án tốt hơn.
- [ ] **Design doc từng thành phần/hàm** (tại sao chọn + so V2/V1).

### M3 – Threading Level 2 (tuần 4)
- [ ] ForkJoinPool chung; Reconstruction task/node.
- [ ] Mining chia cây con theo ngưỡng độ sâu; join deterministic.
- [ ] Construction song song + merge (có switch).
- [ ] Test determinism pool {1,2,4,cpu}.

### M4 – Nghiệm thu đúng đắn (tuần 5)

- [ ] minOcc>0: TC9–TC18 + E1–E10, so double đầy đủ với V2.
- [ ] Đối chiếu từng trường hợp: DO node, DUBO, Z, UB', DOP.

### M5 – Benchmark đầy đủ (tuần 6)

- [ ] Scalability: kosarak 200K→990K, chainstore 1.1M (cắt dòng) → runtime & memory theo N.
- [ ] Bảng so V1/V2/V3: runtime 3 pha, peak memory, throughput, latency, scalability.

### M6 – Tài liệu & hoàn tất (tuần 7)
