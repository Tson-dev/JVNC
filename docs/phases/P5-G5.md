## 0. Vì sao ưu tiên G5 ngay bây giờ

**G3 (V3 Optimized) đã xong** (2026-10-11): V3 viết lại, **16 test**, toàn reactor **121 test xanh**, `minOcc=0 ≡ V1/V2`, `minOcc>0 ≡ V2` bit-for-bit, và **nhanh hơn V2 2.3–28×** (heap thấp hơn). Theo lộ trình, bước tiếp là **G4 (V4 Extreme)** — nhưng đó là **tối ưu tiếp** trong khi:

- **Cổng giao tiếp G5 vẫn trống**: chưa có module `dhopm-cli`, chưa có giao thức chốt cho FE.
- **FE (`javanc`) bị chặn** theo đúng thỏa thuận D7: hiện vẫn "bridge" gọi thẳng `MiningEngine` trong process — trái mô hình "một Manager duy nhất".
- **Giá trị V1/V2/V3 chưa có bề mặt trình bày** nếu thiếu G5 + G6.

⇒ **Đề xuất: tạm hoãn G4, dựng G5 trước.** Lập luận đầy đủ ở `plans/07-G5-PIVOT-ANALYSIS.md`.

## 1. Mục tiêu

1. Dựng **một điểm vào duy nhất** cho FE/tool giao việc và lấy kết quả: module `dhopm-cli` (`Manager`).
2. Chuẩn hoá **hợp đồng giao thức** (đặc tả JSON) làm ranh giới FE ↔ BE — **không share class Java** với FE (D7).
3. Manager **tách yêu cầu con theo version**, chạy nhiều version cùng lúc, **gộp kết quả** theo schema chuẩn, kèm **`windowInfo`** và **cảnh báo validator**.
4. Giữ **hot path thuật toán không đổi**: Manager chỉ là *client* của API mở `dhopm-common` (D6 / P5).
5. Bảo toàn hành vi cũ: `--json mine` phải cho **cùng kết quả** với CLI văn bản hiện có; golden TC1–TC8 vẫn xanh.

## 2. Phạm vi

**Trong phạm vi (G5):**
- Module/entry `dhopm-cli`: chế độ **one-shot** (`--json`), `serve` (JSONL), và **kênh TCP `localhost:7079`** (D46).
- `VersionRegistry` (hardcode 4 factory V1–V4 — YAGNI, xem `DECISIONS.md` §6) + `EngineFactory`.
- `CommandDispatcher` phủ **bộ lệnh chuẩn** (D27) + `info`/`version` + `config get/set/list` + `fetch`, theo cú pháp **Hybrid** (D47).
- `JobManager` (tách yêu cầu con theo version) + `ResultAggregator` (gộp, chuẩn hoá schema).
- `SessionManager` (trạng thái stream theo session; `feed`/`mine`); `stream --step` + `--detail 0/1/2`.
- `ParameterEcho` (trả `windowInfo` + mã cảnh báo validator).
- `ResultStore` (lưu `mine_<yy-MM-dd>_<NNN>.txt`, `isLog`/`--export`, `fetch`) (D48) + config 3 cấp (D49).
- **Tài liệu hợp đồng** `plans/08-FE-CONTRACT.md` + test contract.

**Ngoài phạm vi (để sau / đã bác bỏ):**
- ~~SPI/plugin discovery~~, ~~`ResourceManager` → native Win/Mac~~, ~~Recovery`/`JobLedger`~~ (xem `DECISIONS.md` §6).
- Mode `log` (superset của `--detail`, tốn tài nguyên nhất) — **để sau** (D47).
- Không tối ưu thuật toán, không sửa V1/V2/V3, không làm V4.

## 4. Kiến trúc `dhopm-cli`

```
implementation/dhopm-cli/
  ├── ManagerMain            entry: "one-shot <command>" hoặc "serve"
  ├── transport/
  │     ├── StdioJsonLines   one-shot: đọc/ghi 1 dòng JSON (--json)
  │     ├── ServeLoop        daemon JSONL (stdio)
  │     └── TcpTransport     TCP cổng 7079: BE luôn mở, chờ FE connect (D46)
  ├── discovery/             BE accept connect + xác thực `hello`; FE tự dò localhost→LAN (design doc riêng)
  ├── CommandDispatcher      ánh xạ cmd → handler; validate (∂,f,minOcc); cú pháp Hybrid (D47)
  ├── VersionRegistry        Map<version, EngineFactory> — hardcode v1..v4 (YAGNI)
  ├── JobManager             request → sub-job/version; id, trạng thái, tiến trình
  ├── ResultAggregator       gộp kết quả; schema chuẩn; ép cùng (∂,f,minOcc)
  ├── SessionManager         DHO-List per session; feed/mine; khóa tuần tự theo session
  ├── ParameterEcho          windowInfo + cảnh báo validator (mã ổn định)
  └── ResultStore            lưu mine_<yy-MM-dd>_<NNN>.txt (isLog/--export) + `fetch` (D48)
        │
        ▼ (chỉ dùng API dhopm-common — D6)
  Engine · PhaseAwareEngine · ProgressAwareEngine · WindowAwareEngine · TimedEngine
  MinerConfig · Pattern · MineResult · WindowInfo · ParameterValidator · WindowMath
```

**Quan hệ với CLI từng version:** CLI hiện có (`dhopm.v1.cli.Main`, `dhopm.v2.cli.Main`, `dhopm.v3.cli.Main`) **giữ nguyên** và tiếp tục là "client mẫu của API" (D6/P4). Manager **không** spawn các `Main` này; nó gọi trực tiếp `EngineFactory` trong process (OP-3). Nhờ vậy không nhân đôi parse CLI và không tốn I/O tiến trình.

## 5. Bộ lệnh & giao thức

Manager phủ **đúng bộ lệnh chuẩn** (D27), chốt theo cú pháp **Hybrid** (D47) — positional `<dataset> <partial> <factor> <limit>` + `--minOcc` bắt buộc + flag tuỳ chọn:

| Nhóm | Lệnh | Nguồn số liệu |
|---|---|---|
| Khai phá | `mine` · `detail` · `stream` | `Engine.loadBatch` + `mineNow` |
| Khai phá | `stream --step` · `--detail 0/1/2` | listener `PhaseAware`/`Progress`/`Window` |
| Kiểm tra | `golden` · `inspect` | TestKit · `TransactionSource` |
| Cửa sổ | `window` · `validate` · `sweep` | `WindowMath` · `ParameterValidator` |
| Quản trị | `info` · `version` · `config get/set/list` | manifest tĩnh (không dò nội bộ — P1) |
| Phiên | `session.create` · `feed` · `session.mine` | `SessionManager` |
| File | `fetch <fileID>` | `ResultStore` (D48) |

**Đặc tả chi tiết (schema request/response, mã lỗi, ví dụ) nằm ở `plans/08-FE-CONTRACT.md`** — đây là **sản phẩm hợp đồng chính** của G5, không lặp lại ở đây.

## 7. Tiêu chí chấp nhận (testable)

- [ ] **Tương đương kết quả:** `--json mine` == CLI văn bản cũ (cùng `inspect`), cho cả V1/V2/V3.
- [ ] **Kết quả luôn có DOPs:** mọi lệnh mining (`mine`/`detail`/`stream`) đều trả **danh sách DOPs** (khác nhau ở cách trình bày) — D47.
- [ ] **`window` khớp bảng:** `W(f,minOcc)` trả về **khớp `WindowMathTest`** và bảng tra `plans/00` §2.3.1.
- [ ] **`validate` mã ổn định:** trả đúng `MIN_OCC_TOO_LARGE`, `WINDOW_TOO_LARGE`, `PARTIAL_ZERO`, `INFEASIBLE_PARTIAL`; `validate` **không có `TL`** thì chỉ trả giá trị `…Asymptotic` + `…Exact=null` (D38).
- [ ] **Multi-version:** `perVersion` đúng từng version; khác `(∂,f,minOcc)` ⇒ `MISMATCHED_WINDOW_CONFIG`, **không gộp** kết quả không tương đương (D20/C12).
- [ ] **Bắt buộc khai báo:** thiếu `(∂,f,minOcc)` ⇒ `MISSING_PARAMETER` (D28/D41), **không** lấy mặc định thư viện.
- [ ] **`stream --step`/`--detail`:** `--detail 2` chỉ log khi pattern đạt DOP; `--detail 1` thêm UBDO/DO khi điều kiện đúng; `--detail 0` log cả điều kiện sai (D47).
- [ ] **`isLog`/file:** khi bật (hoặc `--export`), ghi `mine_<yy-MM-dd>_<NNN>.txt` qua hàng đợi + thread riêng (không chặn worker); `<NNN>` **reset theo ngày**; `fetch` lấy đúng nội dung; FE **sao lưu cục bộ** (D48).
- [ ] **Kênh TCP `7079`:** BE luôn mở cổng; FE dò localhost → LAN; sai contract ⇒ `BE_NOT_FOUND`/`PROTOCOL_MISMATCH` (D46).
- [ ] **Config 3 cấp:** `config get/set/list` đúng thứ tự `default < file JSON < args` (D49).
- [ ] **Stream dài:** có progress/log event, **không đóng băng** (dùng `--limit` khi cần).
- [ ] **Golden không đổi:** TC1–TC8 vẫn xanh sau khi thêm Manager.
- [ ] **Hợp đồng FE:** FE chạy chỉ với `BackendClient`, 0 `import dhopm.*`.
- [ ] **Zero-overhead:** tắt listener ⇒ kết quả bit-for-bit không đổi (INV-E).
